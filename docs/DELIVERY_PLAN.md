# MVP delivery plan

## Phase 0 — Foundation (this repository)

- Standalone monorepo and local infrastructure
- Shared destination/access/assessment contracts
- Core database model and representative seed
- Public website demo and Android-ready Expo shell
- Versioned API and rule-based assessment tests
- Security and privacy baseline

## Phase 1 — Field-ready alpha

- Account/session implementation and Vehicle Passport
- Map provider and geospatial destination search
- Admin moderation screens and content expiry jobs
- Media upload pipeline with metadata stripping
- 20–30 destinations researched with a field checklist
- English and Sinhala interface; Tamil content model retained
- Analytics, crash monitoring, backups, and staging deployment

## Phase 2 — Closed pilot

- Verified Journey capture and anti-fraud signals
- Calibrated Journey Confidence Score
- Ask Buddy retrieval over approved evidence only
- Recent traveller relay questions and opt-out
- Responsible Reveal and guardian workflow
- Accessibility testing and low-connectivity behaviour

## Phase 3 — Public MVP

- Independent security review and privacy impact assessment
- Play Store release process, signed AAB, support and deletion flows
- Moderation coverage, incident response, terms and privacy notices
- Dataset quality audit and seasonal-condition runbook

## Destination completion checklist

Each launch destination needs all five access-graph nodes (where applicable), verified coordinates, final-road surface, supported vehicle categories, parking point, walking distance and difficulty, landmarks, public transport chain, facilities, connectivity, current status, evidence dates, source classification, environmental rules, media permissions, and at least two independent confirmations.
